# 改动检查清单（修一处必须全查同类）

> 这份清单不是提醒，是**纪律**。本项目已经因为"只修一半"连续踩坑两次：
> - v3.11.2 修了桌面版缺月线，**漏了手机版**
> - v3.11.3 才发现手机版 `PERIODS.CR` 同样缺 `month`

## 一、为什么必须全查同类

本项目的功能分布在**多个层级、多个端**：

| 层级 | 位置 | 特点 |
|---|---|---|
| 后端算法 | `server/lib/*.js` | 单一实现，改动影响全部 |
| 后端配置 | `sources.js` / `constants.js` | 名称、周期、市场定义 |
| 桌面前端 | `web/js/pages/*.js` | 渲染 + 交互 |
| 手机前端 | `web/m/js/mobile.js` | **独立实现一份**，最容易漏 |
| 图表 | `web/js/chart.js` | 独立绘制逻辑 |

实测分布（同一功能出现的处数）：

| 功能 | 前端 | 后端 | 风险 |
|---|---|---|---|
| 周期列表 | 4 处 | 3 处 | ⚠️ 各存一份 |
| 市场列表 | 6 处 | 4 处 | ⚠️ 各存一份 |
| 信号类型 | 2 处 | 5 处 | ⚠️ 各存一份 |
| 中枢渲染 | 4 处 | 9 处 | ⚠️ 各存一份 |
| 背驰判断 | 7 处 | 7 处 | ⚠️ 各存一份 |

## 二、动手前的四问

修任何 bug 前，先回答这四个问题，**答案写进提交信息**：

### 问 1：这个功能在手机版有吗？

```bash
grep -rn "<你的关键词>" web/m/js/mobile.js
```

有 → 必须同时修，或明确说明为什么手机版不受影响。

### 问 2：这个配置是不是别处也定义了一份？

```bash
node scripts/audit-misleading.js    # 规则⑤ 会报「配置漂移」
```

### 问 3：前后端是不是各维护一份？

```bash
# 例：改周期
grep -rn "PERIODS\|periods:" server/lib/sources.js server/lib/constants.js web/js/pages/structure.js web/m/js/mobile.js
```

### 问 4：这个数字/文案是从数据来的，还是写死的？

```bash
node scripts/audit-misleading.js    # 规则②③ 会报「固定话术」「计数在括号内」
```

- [ ] 验证：桌面 + 手机都要切一遍

### ② 改市场

- [ ] `server/lib/constants.js` 的 `MARKETS` / `MARKET_ORDER`
- [ ] `web/js/ui.js` 的本地兜底值
- [ ] `web/m/js/mobile.js` 的市场横条
- [ ] 验证：每个市场都要能切

### ③ 改信号/买卖点

- [ ] `server/lib/chan.js`（检测逻辑）
- [ ] `server/lib/btengine.js`（回测用到的信号）
- [ ] `web/js/ui.js` 的 `SIG_SHORT` / `SIG_CLS`
- [ ] `web/m/js/mobile.js` 的信号显示
- [ ] 验证：回测 + 图表 + 手机都要看

### ④ 改结构式/文案

- [ ] 先问：这句话是**固定话术**还是**从数据生成**？
- [ ] 固定话术只能用于讲概念，不能用于讲"当前是什么"
- [ ] 关键数字写在**主文案**里，不放括号
- [ ] 验证：`node scripts/audit-misleading.js`

### ⑤ 改接口返回字段

- [ ] 前端所有消费该字段的地方（`grep -rn "字段名" web/`）
- [ ] 手机版单独再查一遍
- [ ] 验证：`node scripts/apicheck.js`

## 四、审计脚本能自动抓的（5 条规则）

```bash
npm run check:misleading
```

| # | 规则 | 抓什么 |
|---|---|---|
| 1 | 删括号 | `replace(/（.*?）/, '')` 丢失关键限定 |
| 2 | 固定话术 | 含结构术语、无插值、不在 if 分支内 |
| 3 | 计数在括号内 | 把"N 个中枢"塞进括号 |
| 4 | 周期不一致 | 前后端周期列表漂移 |
| 5 | 配置漂移 | 名称在 `constants.js` 之外重新定义 |

**自动抓不到的**：逻辑错误、算法边界、语义误导。这些必须靠人工判断。

## 五、提交前必跑

```bash
npm test                 # 单测
node scripts/audit-misleading.js   # 5 条规则
npm run check:all        # 全套门禁
```

## 六、两次真实教训

### 教训 1：只修了桌面

v3.11.2 修 `PERIODS.CR` 缺 `month`，只改了 `web/js/pages/structure.js`。
用户截图是桌面版，于是我就只看了桌面。

**结果**：手机版 `web/m/js/mobile.js` 里同样的 `PERIODS.CR` 也缺 `month`，
直到 v3.11.3 盘点配置时才被发现。

**正确做法**：看到"周期列表"这个词，就该 `grep -rn "PERIODS"` 全项目查一遍。

### 教训 2：测试失败先怀疑测试

flowcheck 报「算卦换卦失败」，我查了 10 分钟后端 nonce 逻辑——
后端 8 次起卦给出 8 个不同卦名，一直是好的。

**真正原因**：测试正则 `^(乾|兑|离|震|巽|坎|艮|坤)` 先命中了页面里的"离宫"，
抓到的是**宫位**不是**卦名**。

**正确做法**：测试失败时，先用同样的操作手工验证一次产品行为，
确认是产品坏还是测试坏。

## 七、第三次教训：名称映射的措辞不一致（v3.11.5）

做"收敛信号类型 9 处定义"这件事时，发现一个更隐蔽的问题：

```js
// server/lib/chan.js（用户实际看到的）
const SIGNAL_NAME = { '1B': '第一类买点', … };
// server/lib/constants.js（v3.11.3 新建，还没被使用）
const SIGNALS = { '1B': '一类买点', … };
```

**同一个信号，两处措辞不同**。当时还没出问题，只是因为 constants 那份没被引用。
一旦有人把 constants 接上去，界面上就会突然从「第一类买点」变成「一类买点」。

### 统一时的原则

**以用户已经看到的措辞为准，改代码去迁就它，而不是反过来。**

- 用户界面上已经是「第一类买点」→ 改 `constants.js` 加入"第"字
- 绝不能因为"constants 是新建的权威源"就改掉用户可见文案

### 加进审计第 5 条

`信号名称映射` 现在也是禁止重复定义项之一，注入回原状会精确报错。

## 八、第四次教训：硬编码市场子集（v3.11.6）

用户要求"合并"。查市场列表 12 处时，发现**三类情况要分开对待**：

| 类型 | 例子 | 处理 |
|---|---|---|
| 全集引用 | `app.js` 校验 URL 里的市场参数 | ✅ 改为从 `U.MK` 派生 |
| **漏写的子集** | `['A','HK','US','CR']` 本该是全集 | ❌ **真 bug，必修** |
| 有意的子集 | 数据源只覆盖 4 个市场 | ✅ 保留 |

### 抓出的三个真 bug

**① 雷达页看不到期货自选股**

```js
// 后端自选股有 6 个市场（CNF 5 只、USF 5 只）
// 前端只遍历 4 个 → 期货自选股完全看不到
['A', 'HK', 'US', 'CR'].reduce(...)
```

修复后：`A股·6 港股·4 美股·4 加密·4 国内期货·5 美期货·5`，共 **28 只**（原只算 18 只）。

**② 数据源表漏掉期货**

`web/js/pages/sources.js` 同样硬编码 4 个，而后端 `mk.markets` 有 6 个。

**③ 手机脉冲卡片 CNF/USF 永远是 0**

```js
// 生成卡片时遍历 6 个市场
[['A','A股'], …, ['CNF','国内期货'], ['USF','美期货']]
// 更新数据时只遍历 4 个 → 后两个卡片永远是 0
['A','HK','US','CR'].forEach(...)
```

**这一条最典型**：同一个文件里，生成和更新用了两份不同的市场列表。

### 审计规则加强

第 5 条「配置漂移」新增 `市场全集硬编码` 检测：

```js
/\[\s*['"]A['"]\s*,\s*['"]HK['"]\s*,\s*['"]US['"]\s*,\s*['"]CR['"]\s*\]/
```

只查"疑似全集"（4 个以上连续市场代码），单个市场引用不算。
`sources.js` 的数据源能力声明是合法子集，加白名单。

**这条规则上线后立刻抓到了手机版那一处** —— 那是我原本差点漏掉的。

## 八点五、第五次教训：同文件内两处循环各写一份（v3.12.1）

用户要求专门扫这个模式：

> **同一个文件里，生成用 6 个、更新用 4 个**。这类"两处逻辑本该一致却各写一份"
> 比跨文件重复更隐蔽。

### 为什么更隐蔽

| | 跨文件重复 | 同文件重复 |
|---|---|---|
| 发现难度 | grep 能看到多份 | 读者容易当成"各自独立的逻辑"而放过 |
| 改的时候 | 会意识到要同步 | 只改眼前那处 |
| 后果 | 平台间不一致 | **同一个页面上自相矛盾** |

手机版那个 bug 就是：生成脉冲卡片遍历 6 个市场、更新数据只遍历 4 个，
结果 CNF/USF 两张卡片**永远显示 0**。

### 这次扫到的

| 位置 | 形态 | 结果 |
|---|---|---|
| `mobile.js` | `['A','HK','US','CR','CNF','USF']` 硬编码 **3 遍**（结构页/算卦/自选池） | 已提取为 `MK_ALL()` |
| 其他文件 | 无 | —— |

> 注意：这 3 处**内容是对的**（都是全 6 个），所以运行时没报错。
> 隐患在于"下次加市场要改 3 个地方"。

### 审计第 6 条

```
同一文件内，相同的数组字面量循环出现 ≥2 次 → 报警
```

只查"字面量常量列表"（以引号或数字开头），忽略动态表达式。

**注入验证**：把两处 `MK_ALL()` 改回 `['A','HK','US','CR']`，
审计同时报出**「市场全集硬编码」和「同文件重复列表 ×2（行 959,1264）」**——
两条规则交叉命中。

### 顺带修掉服务崩溃的真因

排查过程中服务挂了 3 次（health 返回 000），一直归因于"环境回收"。
这次认真查了：

**根因：`server/index.js` 根本没有 `uncaughtException` / `unhandledRejection` 处理器。**

任何一个未捕获的异步异常都会直接杀掉整个进程，而且**日志里什么都不留**。

修复：
```js
process.on('unhandledRejection', (reason) => logCrash(...));        // 记日志，不退出
process.on('uncaughtException', (err) => { logCrash(...); exit(1); }); // 刷盘后退出，由 service 拉起
```
崩溃写 `data/server-crash.log`，下次崩了能直接查。

> 教训：**进程会"莫名其妙"消失时，先看有没有全局异常兜底**。
> 没有兜底的话，所有崩溃都是无声的。

## 九、哪些"重复"不该合并

用户说"合并"之后，我逐处判断，结论是**并非所有重复都要合并**：

| 位置 | 看起来重复 | 实际职责 | 结论 |
|---|---|---|---|
| `defense.js` `buySignals` | 信号列表 | 业务语义（哪些算买入） | 保留 |
| `btengine.js` 注释 | 信号列表 | 只是示例注释 | 保留 |
| `ui.js` `SIG_SHORT` | 信号名 | 前端短名（空间受限） | 保留 |
| `highlight.js` `buy1` | 信号名 | 教学标注主题键 | 保留 |
| `sources.js` 数据源支持市场 | 市场列表 | 能力声明（只覆盖 4 个） | 保留 |
| `game.js` 抽样池 | 市场列表 | 带权重的业务抽样 | 保留 |

**判据**：合并的是"同一份信息被维护成两份"，不是"不同层各自需要一份"。
强行合并不同职责会引入耦合，反而更容易出错。

## 十、一句话总结

> **改任何一个"名称/列表/文案"，先 grep 全项目；改任何 bug，先问手机版有没有。**
