# 缠关 · 108 —— 108 课闯关小游戏（独立应用）

> 独立部署在 `/game/`，不依赖工作站外壳，可以直接当成一个单独的小游戏测试；稳定后再考虑并入主站。

## 1. 它解决什么问题

108 课是纯理论，读完记不住。这个小游戏把每一课变成一道**基于真实行情**的题：

| 题型 | 玩家要做什么 | 判分方式 |
| --- | --- | --- |
| 看走势 `predict` | 看截断到某一天的图，判断接下来 12–20 根日线涨/跌/震荡 | 方向对不对（±1.5% 为界），再按幅度给分；与缠论信号同向额外加分 |
| 找买卖点 `signal` | 在图上点出买卖点所在的 K 线 | 与标准答案的 K 线距离（≤1 根 100 分，每远 1 根 −6） |
| 框中枢 `pivot` | 拖一个框把中枢框出来 | 与真实中枢区间的 IoU 开方映射到 0–100 |
| 判背驰 `beichi` | 判断最后一段有没有背驰 | 二选一，附力度对比数字 |

难度分四档：1–27 青铜 / 28–54 白银 / 55–81 黄金 / 82–108 王者；难度越高，隐藏的 K 线越多（12/14/16/20 根）。

## 2. 关卡从哪来

- 关卡直接映射 `server/lib/chan-lessons.js` 的 108 条课程索引，按 14 个主题分章；
- 主题决定题型（`THEME_MECHANIC`），例如「中枢·走势类型」章全部是框中枢，「三类买卖点」章全是找买卖点；
- 每关的市场与标的由 `levelPlan(no)` 确定性生成（A股/港股/美股/加密四个池子轮换），同一关永远是同一个标的，不会因为刷新而"换题"。

## 3. 答案为什么不会被看穿

1. `GET /api/game/level` 只返回**截断前**的 K 线（不含隐藏段），响应里没有任何答案字段；
2. 同时下发 `token = HMAC-SHA256(no|market|code|cutoff)`；
3. `POST /api/game/answer` 用同一份数据在服务端重算答案再比对，token 不对直接拒绝；
4. 所以前端拿不到答案，伪造 token 也没用；**同一次出题只能提交一次**（判分不落状态，靠 token 与服务端重算保持一致）。

`scripts/apicheck.js` 里有专门的断言：「闯关不泄题」（检查出题响应不含 `dir` / `revealedBars`）与「闯关防伪造 token」（400）。

## 4. 数据

- 每次出题都走 `/api/klines` 那条适配链（腾讯 → 新浪 → 东财 → Binance/纳斯达克），带 60s 缓存；
- 需要至少 120 根日线，不够就返回「行情样本不足，暂时开不了这一关」；
- 隐藏段是**已经发生的历史**，所以判分即时且确定；同时因为每次取的是最新行情，题目本身是「最新数据 + 随机截断」，练的是结构识别而不是背答案。
- 如果出题后行情又走了几根导致 cutoff 变化，token 会失效并提示「这道题的数据已过期，重新开一关吧」——这是有意设计（避免用旧 token 套新数据）。

## 5. 前端

- 复用主站 `web/js/chart.js` 画 K 线（同一个渲染器，视觉一致），开始时关闭笔/线段/中枢/买卖点等标注，交卷后才打开并揭示答案；
- 进度存 `localStorage['changuan-progress-v1']`：`{levels:{no:{score,stars}}, streak, best}`；
- 星级：≥90 三星 / ≥70 两星 / ≥45 一星；只记录最高分；
- 未通关的关卡在 UI 上锁住，只能顺序推进（URL 直开由 `unlockedMax` 判定，越级会被拦）。

## 6. 怎么测

```bash
npm test                 # 含 5 个关卡引擎单测（地图 108 关 / 难度分档 / 规划确定性 / 题目多样性）
npm run check:api        # 含 5 项闯关接口（地图、出题、不泄题、判分、伪造 token）
npm run check:flow       # 含 6 步闯关链路（地图→出题→作答→判分→讲解→进度落盘）
```

浏览器里直接开 `http://127.0.0.1:8931/game/`，手机尺寸 390×844 已验证。
